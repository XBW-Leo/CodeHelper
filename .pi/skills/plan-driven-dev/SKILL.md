# 计划驱动开发（Plan-Driven Development）

## 何时使用

- 任务涉及多个文件或多个模块的改动
- 用户明确要求先规划
- 任务存在多种可选方案，需要权衡
- 任务影响面较大，需要可回滚的推进方式

## 工作流

1. **调研（Investigate）**：只读方式理解现状。阅读相关文件、运行只读命令（`git status`、`rg`、`ls`），不要修改任何文件。
2. **规划（Plan）**：输出阶段化计划。每阶段包含：目标、具体步骤、涉及文件、验收标准；同时列出风险、假设和需要用户确认的决策点。
3. **确认（Confirm）**：除非用户明确说"直接做"，否则停在计划阶段等待确认。计划中的决策点必须清晰标注。
4. **实施（Implement）**：按计划小步实现。一次只改一个相关文件组，每步之后运行编译/测试/校验。
5. **验证（Verify）**：运行项目约定的校验与测试命令，确认无回归。
6. **报告（Report）**：总结改动内容、验证结果、遗留事项。

## 规则

- 规划阶段绝不写业务代码。
- 每个阶段必须有明确的完成标志，没有完成标志的阶段不要开始。
- 计划发生变化时，先更新计划再继续实施。
- 遵循 AGENTS.md 中的项目约定（Git 规则、文档同步、校验命令）。
