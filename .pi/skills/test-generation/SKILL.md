# 测试生成（Test Generation）

## 何时使用

- 为函数 / 模块补充单元测试
- 新代码需要测试骨架
- 覆盖率不足需要补测试

## 工作流

1. **确定目标**：文件 / 函数 / 模块。
2. **调研**：
   - 通读目标代码与依赖，理解每个导出的行为、输入输出、边界与抛错条件
   - 确认测试框架与风格：`node:test` / vitest / jest；import 方式、断言库、文件命名（如 `*.test.js`）
   - 参考项目已有测试文件，保持一致
3. **生成骨架**：
   - 每个导出函数至少三类用例：正常路径、边界条件、错误路径
   - 用例命名描述行为（如 `add 返回两数之和`），不用 `test1` / `test2`
4. **只改测试文件**：不修改业务代码；测试暴露 bug 时报告根因，不擅自修复。
5. **运行验证**：执行测试命令，确认通过；未通过的用例标 TODO 并说明原因。
6. **报告**：生成的文件、覆盖的导出、运行结果、遗留事项。

## 规则

- 遵循项目已有测试风格
- 不生成脆弱快照、不测试实现细节（内部变量、私有函数，除非必要）
- 不删除或弱化已有测试
- 测试失败必须解释根因，不掩盖问题
