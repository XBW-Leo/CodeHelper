# 行为不变重构（Refactor）

## 何时使用

- 提取函数 / 组件、拆分过大的模块
- 重命名、简化重复代码
- 替换实现方式（如手写逻辑换成标准库）

## 工作流

1. **理解现状**：通读目标代码及其调用方、数据流；此时不修改任何文件。
2. **建立基线**：运行现有测试 / 校验命令，确认全部通过；基线不绿不动手（除非任务本身就是修复测试）。
3. **出方案**：说明目标结构、实施步骤、影响面（哪些调用方会受影响）、风险。
4. **确认**：除非用户明确说"直接做"，否则停在方案阶段等待确认。
5. **小步实施**：一次只做一个重构步骤，每步后运行测试 / 校验；实施前用 git 记录当前状态，保证可回滚。
6. **回归验证**：运行与基线相同的测试 / 校验，全部通过；如行为有变化，明确说明变化点。
7. **报告**：改动内容、涉及文件、验证结果、风险与后续建议。

## 规则

- 行为不变：不顺手加功能、不修无关 bug、不改变对外接口（除非用户明确要求破坏性变更）。
- 改动最小：不重写不必要的大段代码。
- 一次一步：每个步骤独立可验证、可回滚。
- 文档同步：接口或行为有变化时，更新相关文档。
