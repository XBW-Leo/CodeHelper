# 深度调试（Debug）

## 何时使用

- 用户报告 bug 或行为异常
- 测试失败但原因未知
- 反复猜测式修改无效，需要系统定位

## 工作流

1. **复现（Reproduce）**
   - 明确触发条件：输入、环境、操作步骤
   - 先运行一次，确认问题确实存在且能稳定复现
   - 无法复现时，收集现场信息：报错堆栈、日志、输入样例

2. **最小化（Minimize）**
   - 缩小排查范围：隔离无关代码，或用最小脚本复现
   - 目标：得到"最小可复现样例"

3. **定位根因（Root Cause）**
   - 形成假设 → 用证据验证（读代码、加日志、跑隔离测试）
   - 一次只验证一个假设，不要同时改多处
   - 找到根因后**先向用户说明**，再动手修复

4. **修复（Fix）**
   - 最小改动修复根因；不顺手重构、不扩大范围
   - 不通过删除测试、放宽断言或跳过失败来掩盖问题

5. **回归（Verify）**
   - 新增或更新测试覆盖该 bug，防止复发
   - 运行相关测试与项目校验，确认修复且无回归

## 规则

- 一次只验证一个假设
- 修复前必须能说清根因，说不清就继续定位
- 完成后报告：复现条件、根因、修复方式、验证结果、遗留事项
